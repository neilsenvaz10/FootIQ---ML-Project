# Live demonstration script (2.5 to 3 minutes)

> **Scope update (Phase 4.18): FootIQ now supports exactly SIX competitions** - the five domestic leagues (Premier League, La Liga, Bundesliga, Serie A, Ligue 1) and the UEFA Champions League. The Europa League, Conference League, World Cup, Nations League and Copa America were removed from the active scope (their data is preserved, nothing in the application shows or predicts them). Anything below that describes them is history. Authoritative description: `docs/mini-project/phase4/P4_18_SIX_COMPETITION_SCOPE.md`.

**Before you start (2 minutes, not part of the 3).** Use a private database copy so the demo cannot touch the production store (`SETUP_AND_RUN.md` §4). Start the backend, wait for `/api/health` → `"club_prediction_ready":true`, start `npm run dev`, open `http://localhost:5173` at desktop width and check there is no red banner. Keep a second tab on `Models`. Timings below were measured on the project machine (World Cup 1,000 simulations: 2.2 s pre-tournament, 0.4 s archived; points-only season simulation about 6 s; a match prediction and a comparison under 0.1 s).

## Fallback plan

* **A simulation is slow (more than 15 s):** say "it is running 10,000 draws", wait once; if the spinner is still there, reload and rerun with **1,000** simulations (World Cup pre-tournament 2.2 s; season simulator 1,000 runs). Pre-tournament at 50,000 takes about 80 s: never use it live.
* **"Club models are warming up":** the club history takes 20–30 s after start; use Compare and Leagues meanwhile, or open the Models page.
* **Red "Cannot reach the backend" banner:** the backend is down or an old dev server is running; keep the prepared screenshots in `docs/mini-project/phase4/p4.6/` open as a backup and explain the architecture from `ARCHITECTURE.md`.
* **A different featured match than expected:** it depends on the current date and stored data; read what the banner shows. Never promise a specific fixture.
* **Questions on stale data:** point to the "Data not fresh" chips and `LIMITATIONS.md`: synchronisation is deliberately off.

## One-line close

"Everything shown is computed from stored historical data with frozen, hashed models; every limitation is visible in the interface."
