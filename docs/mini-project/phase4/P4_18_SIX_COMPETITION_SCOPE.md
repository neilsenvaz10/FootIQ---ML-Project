# Final scope: six competitions (Phase 4.18)

Status: **implemented and tested offline; NOT applied to production.** The running backend (pid unchanged since its last launch) still serves the old code in memory; no production database, dataset, rating file, model, snapshot or configuration was modified; nothing was deleted; no Git operation; no provider request; no retraining. The files changed below are on disk and take effect only when the backend is restarted (section 8).

## 1. The scope
Supported (the application shows and predicts exactly these): **Premier League, La Liga, Bundesliga, Serie A, Ligue 1, UEFA Champions League** (`EPL, LALIGA, BUNDESLIGA, SERIEA, LIGUE1, UCL`).
Removed from the active scope: **UEFA Europa League, UEFA Conference League, FIFA World Cup, UEFA Nations League, Copa America** (`UEL, UECL, WC, UNL, COPA`). They are *archived*: their rows, ratings, snapshots and model artifacts are preserved; the application neither shows nor predicts them.

How it is built: `app/config.py` now has `ALL_COMPETITIONS` (all 11, used only by the data-building code so a rebuild keeps the archive), `COMPETITIONS` / `BY_KEY` (the six, used by the application) and `ARCHIVED_COMPETITIONS`. `analytics.matches()` filters the frame to the six, so nothing downstream can leak an archived competition. **Rollback of the scope is a one-line change** (`ACTIVE_KEYS` in `config.py`); the data and artifacts are untouched.

## 3. What the application does now (six competitions)
- **APIs:** `/api/competitions` lists six; every `/api/competitions/{key}/...` route, `/api/predict`, `/api/team` and `/api/data-freshness` answer 404 for an archived key (tested for all five); `/api/worldcup/*` is gone (404).
- **Pages:** the competition selectors (Leagues, Predict, Compare) offer the five leagues and the Champions League; Simulations shows only the domestic season simulator; Models shows the club models and states that the Champions League is not validated; no international or World Cup content remains (tested).
- **Prediction pipeline:** all six predict with the frozen club v1 and v2-r1 and the Elo baseline, no retraining (tested; probabilities sum to 1; the Champions League carries "Not validated (indicative only)" and a note). `predict()` refuses every other competition. `data_through` now reports club results only.
- **Synchronisation:** unchanged: startup-only, Bundesliga and La Liga active, Premier League / Serie A / Ligue 1 prepared but not approved, the Champions League has no update source at all (tested); the freshness indicator shows Bundesliga and La Liga as "Updated when FootIQ starts" and the other four as "Historical only".

## 4. Champions League data (what Phase 4.17B established that still matters)
- **Rules:** UEFA Regulations of the UEFA Champions League 2026/27, Article 18.01 ("Equality of points - league phase", documents.uefa.com, read 2026-10-28) lists exactly the ten criteria the table implements (goal difference, goals scored, away goals, wins, away wins, opponents' points, opponents' goal difference, opponents' goals scored, disciplinary points, club coefficient); criteria 9 and 10 are not in the data, so a surviving tie is shown as a shared rank. The Article is silent on in-progress display (criteria 1-5 only) which stays a presentation convention.
- **Results:** the 18 matchday-2 results (13-14 October 2026) staged from the saved Wikipedia snapshot **match UEFA's own results page 18 of 18** (date, teams, score). They are verified and **not imported**: importing needs your approval. The other 126 league-phase fixtures are in the staging file with dates; their pairings are not independently verified.
- The Europa League, Conference League, World Cup and Nations League verification done in 4.17B (UEFA lists matched 36/36, 18/18 and 104/104; the World Cup final and the four conflicting knockout scores confirmed by FIFA and several outlets) is kept in `data/supervised/phase4/p417/` for the record and is no longer needed.

## 8. Deployment procedure (needs your approval; nothing below has been run)
1. **Pre-checks:** backend healthy, `config/sync.json` startup mode, database integrity ok, `git status` untouched. Note: there is no copy of the pre-4.18 code (no commit); scope rollback is the `ACTIVE_KEYS` line, data rollback is unnecessary (no data changes).
2. **Frontend:** the dev server already serves the new files (hot reload); for a built frontend run `npm run build` in `frontend/`.
3. **Backend restart (the only interruption, about 5 seconds):** stop the running `uvicorn` process tree (port 8000) and start it again as in `SETUP_AND_RUN.md` (`.venv\Scripts\python.exe -X utf8 -m uvicorn main:app --app-dir app --port 8000`). The launch makes one startup refresh for Bundesliga and La Liga (at most 2 requests).
4. **Verify:** `/api/competitions` returns the six keys; `/api/competitions/WC/teams` and `/api/worldcup/simulate` answer 404; `/api/data-freshness` lists six with Bundesliga/La Liga "startup_updated"; `/api/predict` works for each of the six; `/api/sync/status` shows startup mode with 0 scheduler threads; `footiq_service.ps1 audit` passes; the Leagues, Predict, Compare, Models and Simulations pages show only the six.
5. **Rollback:** edit `ACTIVE_KEYS` in `app/config.py` (add the archived keys back) and restart; the removed World Cup routes would need their code restored from the archived modules (still in the repository).
