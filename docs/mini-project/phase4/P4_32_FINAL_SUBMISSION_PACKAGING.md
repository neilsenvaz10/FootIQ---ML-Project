## 3. Reproducibility (clean install of the runtime tier outside the project)
Procedure (`p432/fresh_install.ps1`, `start_pkg_backend.ps1`): copy T1 and T5 to a new folder, create a **new virtual environment with Python 3.12.12**, `pip install -r requirements-share.txt` and `-r app/requirements.txt` (both exit 0; resolved fastapi 0.159.1, uvicorn 0.54.0, numpy 1.26.4, pandas 2.2.1, scikit-learn 1.5.1, httpx 0.28.1), `pip install scipy==1.17.1`, `npm ci` (160 packages, 22 s), start the backend with no contact file and `FOOTIQ_DISABLE_SYNC=1`.
Findings, in order discovered:
1. **The first package was incomplete.** The 23-file "runtime footprint" of Phase 4.25 recorded files that are opened, not code that is imported. The predictor imports project modules from `FootIQ_Club_Model_Development_v2/_scripts` and `FootIQ_ML_Training_Preparation/_build`, and the data-quality code imports `footiq_sources` from `source_adapters_r1`. Without them predictions and the Matches hub returned HTTP 500. Fixed in the manifest (T1) and the setup document now lists them. This would have broken a recipient's copy; it was found only by the clean-install test.
2. `scipy` is imported directly but is not in the requirements files; it normally arrives with scikit-learn; `requirements-final.txt` states it.
3. `py -3.12` did not resolve on this machine (Python 3.12 present through another launcher); the documented alternative is in `SETUP_AND_RUN.md`.
4. `test_miniproject` needs `data/miniproject/matches.csv` and the 73 MB baseline CSV: both are now in the manifest.
5. A process mistake of mine, corrected: my first package backend inherited `FOOTIQ_STORE_PATH` from a reused terminal and read a private copy instead of the package database; I closed it and repeated everything in a fresh terminal with the variable cleared (`store override: []`).
Results on the corrected package instance (own database, own virtual environment): backend ready in about 21 s; **`final_verify.py` 67 of 67 checks passed** (six competitions, results, fixtures, standings, predictions with labels, Champions League 54 + 90, saved simulations 1-3, archived competitions excluded, synchronisation startup-only); frozen models load and predict (Champions League Arsenal v Dortmund 69.1 / 19.6 / 11.3, "Not validated (indicative only)"); **five-league Monte Carlo** (1,000 simulations each, seed 9): Premier League 20 clubs / 300 remaining, La Liga 20 / 281, Bundesliga 18 / 243, Serie A 20 / 300 (provisional), Ligue 1 18 / 234, ranges available for La Liga and Bundesliga only. Tests inside the package: frontend **375 passed, 13 skipped**; backend `test_seasonsim_service.py` and `test_miniproject.py` **64 passed** (32 + 32; the first attempt showed 2 failures caused by my own simultaneous simulation runs changing the same test database and one missing data file, both repeated cleanly).
